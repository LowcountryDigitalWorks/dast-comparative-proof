# Phase B Dependency Notes

All direct package versions are exact-pinned in `package.json`, and the resolved dependency graph is frozen in the committed npm lockfile.

## Runtime

- `hono@4.13.1`: representative LDW HTTP framework for Cloudflare Worker routes.
- `graphql@16.14.2`: local-only GraphQL execution and introspection surface; no external GraphQL service.
- `jquery@3.4.1`: intentionally vulnerable browser-library overlap canary O02; served locally and not used for application logic.

## Development / validation

- `typescript@6.0.3`, `@types/node@24.13.3`: strict typechecking.
- `eslint@10.8.0`, `@eslint/js@10.0.1`, `typescript-eslint@8.65.0`, `globals@17.7.0`: linting.
- `prettier@3.9.6`: formatting.
- `vitest@4.1.10`: unit/integration-style matrix tests.
- `esbuild@0.28.1`: browser bundle and public source-map generation.
- `wrangler@4.127.1`: Cloudflare Worker dry-run build and later authorized disposable deployment.

`package-lock.json` was generated by the GitHub-hosted validation environment from the exact-pinned manifest, committed to the proof branch, and the final validation workflow now uses `npm ci` with read-only repository permissions. The lockfile pins the resolved transitive dependency graph, including the intentionally selected `jquery@3.4.1` overlap canary and the exact Wrangler/workerd toolchain needed for reproducible build/deployment behavior.

Because O02 intentionally pins a known-vulnerable browser dependency, dependency-vulnerability checks are expected to identify it. That expected finding is an overlap canary, not a defect in the proof design.
